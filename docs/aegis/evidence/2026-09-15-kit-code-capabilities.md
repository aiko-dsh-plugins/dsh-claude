# Kit and Code capability integration

Code reuses DSH's skill registry, explicit skill admission, tool execution policy and optional Kit resource tools. Claude still owns its loop, local tools and task orchestration. The official SDK in-process MCP server discovers current scoped connectors without copying their configuration or credentials. Resource operations retain Kit ownership and fail when the kit is unavailable. Native output streams text deltas immediately and separates prose around root tool calls.

The generic Messages transport maps each Claude role to a DSH provider/model pair. A managed query owns its authenticated loopback listener and cancellation. Provider requests use the public LLM service with recursive engine routing excluded. Request/response audit records and exact-content replay lookup use a separate per-session directory, preserving released Session data. Audit values follow credential redaction; transport tokens and provider credentials are not stored. Oversized and unsupported requests fail explicitly.

Keyless integration uses the actual Anthropic TypeScript SDK to consume streams, assemble tool calls and send tool results back through DSH conversion. It checks independent provider roles, early text delivery, response provenance, recorded input, authentication, unsupported content, size limits and listener disposal. The official MCP SDK client exercises the in-process server and DSH argument validation. DSH runtime tests cover connector policy denial, model/user skill invocation rules, native pre-step admission, queued cancellation, turn ownership, resource-tool removal and logged results. Code's built bundle verifies catalog-driven provider policy and native navigation/handoff disposal.

Workflow task names, progress, usage, status, detail and `Query.stopTask()` remain supported. The installed SDK has no public pause/resume/retry control or structured workflow stage graph; none is fabricated. Studio deployment/login is outside this task. These tests do not establish live remote-provider or browser coverage.

Local validation: Claude `pnpm check` passed both typechecks, build and 101 test files (950 tests passed, one skipped). Kit `npm run check` passed with 37 tests; Code `npm run check` passed with two tests. Package dry runs included 28, 44 and 10 files respectively, with no test artifacts, dependency directories or environment files.

The user-authorized preview restart retained the existing DSH home on port 57721. Authenticated HTTP returned 200 and served the exact current Kit, Code and Claude client builds. The Claude doctor endpoint found executable version 2.1.214; no model query or SDK handshake was run during this deployment check. Browser automation was unavailable, so this check supplies no UI screenshot evidence.
